# 권오성 · 카카오 AI 루키 캠프 포트폴리오 작업 정리

> 이 문서는 `portfolio/` 폴더의 **현재 상태**, **완료한 작업**, **남은 작업**을 정리한 작업 메모입니다.
> 최종 확정 시점에는 자리표시자를 모두 채운 뒤 이 문서를 갱신하거나 삭제하면 됩니다.

---

## 1. 목적

카카오 AI 루키 캠프 지원서의 **선택 제출 포트폴리오**입니다.

- 지원서 내용을 뒷받침하는 자료이며, 미제출에 따른 불이익은 없습니다. 단, 가산점이 최대 5% 이내로 반영됩니다.
- 단순 나열보다 **지원서 문항과 연결된 핵심 자료** 중심으로 구성합니다.
- 제출 방식은 **링크(URL) 제출이 기본**입니다.

## 2. 제출 가이드 요약 (카카오 루키 캠프 안내 기준)

### 2-1. 평가 역량 4가지 (지원서 문항과 포트폴리오 섹션의 대응)

| 평가 역량 | 지원서에서 요구하는 내용 | 포트폴리오 섹션 (`index.html`) |
| --- | --- | --- |
| 비전 · 성장 잠재력 | 이루고 싶은 꿈, 캠프에서 배우고 싶은 내용과 연결 | `#vision` 처음 시작은 부모님의 걱정이었습니다 |
| 문제 정의 및 해결력 | 문제를 찾고 근거를 바탕으로 해결 방법을 구체화한 경험 | `#problem` 문제를 나누고, 흐름으로 해결했습니다 |
| 소통 · 협력 | 의견을 나누고 함께 목표를 이룬 경험, 역할 수행 | `#teamwork` 함께 활동한 경험 (**현재 자리표시자**) |
| 프로그래밍 역량 | 코딩·기술 도구를 활용해 본 경험과 배운 점 | `#coding` 코딩으로 만든 것들 |

### 2-2. 포트폴리오 제출 규격

- **제출 방식**: URL 기본. 링크 제출이 어려우면 지원서 5-2번 문항에서 파일 업로드 가능.
- **파일 형식**: PDF, PPT, ZIP, 이미지 (최대 100MB).
- **권장 파일명**: `이름_학교_포트폴리오` → `권오성_대구동중학교_포트폴리오`
- **공동 작업물**: 본인의 역할과 기여도를 명확히 적어야 합니다. (이 프로젝트는 개인 작업이지만, 필요 시 명시)
- **민감 정보 처리**: 타인의 얼굴이나 민감한 정보는 **블러 처리 후 제출**. (스크린샷에 다른 사람 정보나 실제 PC 사용자 정보가 보이지 않도록 주의)
- **본인 작성**: 지원서는 학생 본인이 작성합니다. 과장·허위 내용은 평가에 불이익을 줄 수 있습니다.

### 2-3. 제출 전 확인 사항 (지원서 전체)

- 권역 준수: 현재 재학 중인 학교 소재지에 맞는 회차 선택 (**중복 지원 시 불합격**)
- 오탈자, 연락처, 포트폴리오 링크 최종 점검
- 제출 후 수정 불가, 마감 시각 이후 접수 불인정
- 지원서 하단 **[제출]** 버튼을 반드시 눌러 접수 완료
- 정상 접수 시 확인 문자 발송. 문자가 없으면 운영팀 톡채널로 문의

### 3-3. 자리표시자 목록 (채워야 하는 항목)

`index.html`에서 아래 문구를 검색하면 모두 찾을 수 있습니다.

| 위치 | 현재 문구 | 채워야 할 내용 |
| --- | --- | --- |
| 히어로 | `[스크린샷 추가 예정]` | ComputeDefend 실행 화면 또는 웹 목록 화면 (블러 처리 필요 시 처리 후 삽입) |
| 비전 | `[이루고 싶은 꿈과 캠프 참여 이유 추가 예정]` | 이루고 싶은 꿈, 캠프에서 배우고 싶은 내용 |
| 소통·협력 | `[함께 활동하며 겪은 어려움, 의견을 조율한 과정, 맡은 역할 추가 예정]` | 실제 팀 활동 경험. 없다면 학교·동아리·수업 중 협업 경험을 찾아서 작성 |
| 프로젝트 | `[스크린샷 추가 예정]` | 프로젝트 실행 화면 (히어로와 다른 장면 권장) |

> **주의**: 자리표시자는 **반드시 학생 본인의 실제 경험**으로 채워야 합니다. 없는 경험을 만들어 넣으면 허위 기재로 평가에 불이익이 있습니다.

### 3-4. 디자인 기준

- 사용자 제공 DESIGN.md 기준을 적용했습니다. 딥 틸 히어로 밴드, 그린 필 CTA(`--green: #00ed64`), 흰 캔버스, 12px 카드, 4px 간격 체계.
- 디자인 토큰은 `style.css`의 `:root`에 모두 있습니다. 색을 바꾸려면 여기만 수정하면 됩니다.
- 폰트: Pretendard Variable (원본 Euclid Circular A 대체). 코드 블록은 Consolas 계열.
- 로고나 상표는 사용하지 않았습니다. 색과 구조만 참고했습니다.

### 3-5. 검증 결과 (hallmark 린트)

hallmark 스킬(`nutlope/hallmark`)을 `C:\Users\Kevin\.claude\skills\hallmark`에 설치하고 실행했습니다.

- 정적 검사: **FAIL 0건, WARN 0건**
- 렌더 검사 (1280 / 1440 / 1920 화면, 375px 모바일): **FAIL 0건**
- 남은 REFLEX 2건 (44c 히어로 높이, 79 여백) 은 **waive 처리**했습니다.
  - 사유: 린트가 텍스트 높이만 재기 때문. 실제 1440×900 렌더에서는 코드 카드와 스크린샷 자리가 첫 화면을 채웁니다.
  - 린트가 waive 주석을 인식하지 않아 리포트에는 계속 2건으로 표시됩니다.
- 캔버스 순백색 `#ffffff`: 사용자 디자인 기준이 그렇게 지정하여 waive 처리 (`style.css` 1~3행)

### 3-6. 확인된 동작

- 375px 모바일: 한 열 배치, 가로 스크롤 없음 (스크린샷으로 확인)
- 1440×900 데스크톱: 히어로가 첫 화면 전체를 채움
- 한글 제목 줄바꿈: `word-break: keep-all` 적용으로 단어 중간에서 끊기지 않음
- 포커스 링: 밝은 배경은 진한 녹색, 어두운 섹션은 밝은 녹색으로 대비 3:1 이상 확보
